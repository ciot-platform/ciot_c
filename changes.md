# ciot_c Release

### Changes

**nRF DFU: new session on an open iface (#106):**

* Added `ciot_dfu_nrf_reset(self)`: ends the current session without closing the transport iface. It clears the session state (states, counters, CRC, current object, the ping retry, the SLIP decoder) and releases the iface event handler, so the next `ciot_dfu_nrf_start` begins a new session on the iface that is still open. `ciot_dfu_nrf_stop` now runs the same reset and then closes the iface, as before (`include/ciot_dfu_nrf.h`, `src/common/ciot_dfu_nrf.c`).
* Use it between sessions on the same link, e.g. after a ping-only session (`ciot_dfu_nrf_set_test_mode`), which ends in `COMPLETED` with the iface open. Until now the only way to start again was `ciot_dfu_nrf_stop`, which on ESP32 deletes the UART driver (`uart_driver_delete`); the next start installs it again. On an ESP32 with an nRF52840 bootloader on UART0, every session after a delete + reinstall got no bytes back (ping sent, 0 bytes received, `CIOT_ERR_TIMEOUT`), while sessions that kept the driver installed all got the ping response.
* `ciot_dfu_nrf_start_bootloader` now sets the SLIP decoder and opens the DFU iface before it sends `INIT_DFU`, so the line is idle when the bootloader starts. On ESP32, `uart_driver_delete` disables the TX output, and the DFU UART was only installed again 1.5 s after `INIT_DFU` (in `ciot_dfu_nrf_start`). The first session after the UART was closed (after `ciot_dfu_nrf_stop`, or at the end of a full DFU, where the lib calls it) got no bytes from a bootloader started on that undriven line. Sessions with the UART already open (first one after boot, with UART0 still driven by the console, or after `ciot_dfu_nrf_reset`) were not affected (`src/common/ciot_dfu_nrf.c`).
* When `INIT_DFU` goes over the DFU iface itself (one link shared with the application), `ciot_dfu_nrf_start_bootloader` doesn't touch it: the link keeps the application's handler, framing and config, and `INIT_DFU` goes out in the application's framing, as before. Only `ciot_dfu_nrf_start` switches it to SLIP.
* On nRF, `ciot_uart_start` on a UART that is already open now sends `STARTED` again, as the ESP32 and Windows UARTs do. `ciot_dfu_nrf_start` waits for this event before the ping. On an nRF host with the link opened by `ciot_dfu_nrf_start_bootloader`, the session would otherwise stay in `IDLE` forever (`src/nrf/ciot_uart.c`).
* `ciot_dfu_nrf_start_bootloader` releases a session handler left on the iface before opening it, so the `STARTED` of that open can't move a stale session to the ping. If the iface can't be opened yet, it logs a warning and still sends `INIT_DFU`; `ciot_dfu_nrf_start` opens it, as before.
* `ciot_dfu_nrf_start` resets the SLIP decoder and clears `status.code` and `status.image_written` of the previous session. With the link already open, bytes received before the session (e.g. while the device resets into the bootloader) were kept by the decoder and prefixed to the ping response.
* Validated on an ESP32 + nRF52840 gateway: ping-only sessions 3 in a row, a full DFU at boot followed by ping-only sessions without restarting the ESP32 (3 times), and full DFUs of 86884 and 92532 bytes.
* The first ping refused with `OP_CODE_NOT_SUPPORTED` is now retried once per session. `ping_refused` was never cleared, so the retry was allowed only once per `ciot_dfu_nrf_t`.
* Added `ciot_decoder_slip_reset(decoder)`: drops a partially decoded frame; it returns `CIOT_ERR_INVALID_TYPE` for a decoder that is not SLIP. The DFU reset uses it, so a frame cut at the end of a session no longer corrupts the first response of the next one (`include/ciot_decoder_slip.h`, `src/common/ciot_decoder_slip.c`).
* Tests: `tests/common/ciot_dfu_nrf_test.c` (link opened before `INIT_DFU`, bytes before the session dropped, `INIT_DFU` sent when the open fails, left-over handler released, shared link left alone, reset vs stop on a mock iface, ping retry per session, partial frame) and `test_ciot_decoder_slip_reset_drops_partial_frame`.
